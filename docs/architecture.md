# Architecture

## Package overview

```
github.com/splunk/splunkctl              main.go — calls cmd.Execute()
github.com/splunk/splunkctl/cmd          root command, schema, version, config, registration
github.com/splunk/splunkctl/cmd/generated    emitted object adapters plus hand-maintained support and tests
github.com/splunk/splunkctl/cmd/override     hand-written commands: search, jobs, and others
github.com/splunk/splunkctl/internal/client  Splunk REST HTTP client
github.com/splunk/splunkctl/internal/config  Viper layered config
github.com/splunk/splunkctl/internal/output  output renderer (json/table/text)
github.com/splunk/splunkctl/internal/cmdctx  shared context key (import cycle breaker)
github.com/splunk/splunkctl/codegen          XML → Go code generator (standalone binary)
```

## Request lifecycle

```
user invokes: splunkctl index list

1. main.go → cmd.Execute()
2. Cobra routes to IndexListCmd (in cmd/generated/index.go)
3. PersistentPreRunE (cmd/root.go):
     - config.Resolve(flagHost, flagToken, insecure, output)
       reads: flag → SPLUNKCTL_HOST/TOKEN env → ~/.splunkctl/config.yaml
     - client.New(cfg) — creates http.Client with 30s timeout, optional TLS skip-verify
     - cmdctx.WithClient(cmd.Context(), c) — stores client in context
4. RunE (generated):
     - cmdctx.ClientFrom(cmd) — retrieves client from context
     - builds params map from flags
     - c.Do(cmd.Context(), Request{Method:"GET", Path:"/data/indexes/"})
       → sets Authorization: Bearer <token>
       → sets output_mode=json query param
       → reads response → parseEntries() → []map[string]any
5. output.Print(cmd.Context(), results, outFmt)
     - auto-detects TTY → table format; no TTY (pipe/agent) → json format
     - writes to writer from context (os.Stdout by default; injected in tests)
6. errors surface to cmd.Execute() → errorToCode() → stderr JSON containing only `error` and `code` + exit code
```

## Config resolution

Resolution order (highest priority first):

| Priority | Mechanism | Key |
|---|---|---|
| 1 | CLI flag | `--host`, `--token` |
| 2 | Environment variable | `SPLUNKCTL_HOST`, `SPLUNKCTL_TOKEN` |
| 3 | Config file | `~/.splunkctl/config.yaml` |

Viper is initialized once in `config.Init()` (called from `cmd.init()`). The `Resolve()` function is called on every command invocation from `PersistentPreRunE`.

## Client

`internal/client.Client` wraps `http.Client`. Key methods:

- `Do(ctx, Request) ([]map[string]any, error)` — for commands that consume Splunk's Atom-style JSON feed (`{"entry":[{"name":..., "content":{...}}]}`). Normalizes to flat `[]map[string]any` where `name` is always present.
- `RawDo(ctx, method, path, body) ([]byte, int, error)` — for override commands that need raw bytes (search job polling, results streaming). Path gets `/services` prefix.
- `RawDoAbs(ctx, method, path, body) ([]byte, int, error)` — for absolute paths (e.g. `/servicesNS/...`). No prefix added.
- `RawDoJSON(ctx, method, path, payload) ([]byte, int, error)` — POST/PUT with a JSON body.

ID handling in `Do`: when `Request.ID` is non-empty, it is `url.PathEscape`d and appended to the trimmed path. Slashes in IDs (e.g. monitor input `/var/log/`) become `%2F`.

Error type: `client.SplunkError` (exported). Fields: `Status int`, `Code string`, `Message string`. `cmd/root.go` maps Code to exit codes.

## Output

`output.Print(ctx, data, format)` is the shared write path for structured resource and REST results. Raw or fixed-format responses, interactive prompts, and progress displays may instead use Cobra writers or an established terminal-specific path when that is their explicit, tested contract.

- `format ""` → auto-detect: `*os.File` + `term.IsTerminal` → table; otherwise json
- `format "json"` → `encoding/json` with 2-space indent
- `format "table"` → `text/tabwriter`; `name` column is always first
- `format "text"` → one normalized map row per line via `fmt.Fprintf(w, "%v\n", row)`

Tests inject a custom writer: `ctx = output.WithWriter(ctx, &buf)`.

The established root error handler in `cmd.Execute()` writes exactly `{"error":...,"code":...}` to stderr. `client.SplunkError.Status` participates in error classification but is not included in this external error envelope.

## Generated commands

Only object files in `cmd/generated/` carrying the standard `// Code generated by splunkctl codegen. DO NOT EDIT.` header are emitted by `codegen/`; `shared.go`, `_test.go` files, and `.gitkeep` are hand-maintained. For each eligible XML object, an emitted file:

- Declares one top-level `XxxCmd` (e.g. `IndexCmd`) for the object
- Declares one sub-command per eligible XML `<cmd>` element (e.g. `IndexListCmd`, `IndexAddCmd`)
- Has no business logic beyond flag collection → `clientFrom(cmd)` → `c.Do()` → `output.Print()`

Codegen skips object aliases, objects without an effective URI, objects with a same-name override file, and objects left with no eligible verbs. Within an object it skips command aliases, empty command names, and commands without an effective URI. The generator only writes eligible output; it does not delete an emitted file that is no longer eligible.

`cmd/generated/shared.go` provides the package-level `clientFrom()` shim:

```go
func clientFrom(cmd *cobra.Command) *client.Client {
    return cmdctx.ClientFrom(cmd)
}
```

## Override commands

`cmd/override/` contains hand-written commands for objects or verbs that require multi-step logic or cannot be expressed as a single REST call. Override commands:

- Use the same `cmdctx.ClientFrom(cmd)` pattern
- Register themselves in `cmd/register_overrides.go`
- Can use `c.RawDo()` / `c.RawDoAbs()` for operations that don't fit the Atom-feed model

There are two override models:

- **Preferred full-object replacement:** `cmd/override/<object>.go` makes codegen skip the same-name XML object. Because codegen never deletes files, introducing the full replacement also requires intentional removal of any previously emitted object file and consistent updates to generated and override registration.
- **Legacy explicit partial overlays:** `cmd/register_overrides.go` attaches or replaces override verbs on the checked-in generated `index`, `user`, and `scheduler` parents. This wiring is explicit; it is not performed by codegen. Those same-name override files also make future generator runs skip their parents, so changes must audit the generated parent, override verbs, registration, and artifact ownership together.

## Import cycle solution

`cmd` imports `cmd/generated` to register generated commands. The forbidden back-edge is `cmd/generated` importing `cmd`; that would create an import cycle. Both packages need access to the initialized client, so `internal/cmdctx` provides the shared bridge without that back-edge:

```
cmd                   → cmd/generated
cmd/root.go           → internal/cmdctx → internal/client  (stores client)
cmd/generated/*.go    → internal/cmdctx → internal/client  (retrieves client)
cmd/override/*.go     → internal/cmdctx → internal/client  (retrieves client)
```

`cmd/generated` must not import `cmd`; copied context keys, package globals, or another dependency back-edge are not substitutes for `internal/cmdctx`.

## Annotations

Cobra `Annotations` map keys used:

| Key | Value | Effect |
|---|---|---|
| `"no_client"` | `"true"` | `PersistentPreRunE` skips client init (for `version`, `schema`, `config`, `skill`) |
| `"offline_ok"` | `"true"` | Set by codegen on XML items with `<offline_ok/>` — informational only, not enforced |
| `"describe_path"` | REST path | Path used by `cmdctx.RunDescribe` when `--describe` flag is set |

## Exit codes

| Code | Meaning |
|---|---|
| 0 | Success |
| 1 | General or usage fallback (`USAGE_ERROR` for the fallback) |
| 2 | Reserved; currently unused |
| 3 | NOT_FOUND (HTTP 404) |
| 4 | AUTH_ERROR (HTTP 401/403) |
| 5 | CONNECTION_ERROR (host unreachable, TLS failure) |

Mapped in `cmd/root.go:errorToCode()` by type-asserting on `*client.SplunkError`.

Changing usage failures to exit 2 would be an intentional compatibility change requiring scoped implementation, tests, and documentation; it is not the current behavior.
